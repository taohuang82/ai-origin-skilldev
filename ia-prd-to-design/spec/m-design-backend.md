# m-design-backend — 后端实现要点

> **一句话说明**：在 `backend.md` 中固化 DDD 分层实现、业务流程与时序、跨服务一致性、异步任务、导出与审批编排；条文见本包 `design-backend`（不含接口契约；API 见 **api-contract** 要素）。

---

## 目标

**目标说明**

把领域行为落到**可实现的**后端设计：四层类设计与依赖、流程/时序/规则/异常策略、分布式与本地事务、导出与定时任务、BPM 审批契约；并保持与 **data / integration / api** 各文档的同源引用。

**输出物**

- `backend.md` 中与下列子要素对齐的章节与表格、Mermaid（flowchart / sequenceDiagram / …）。

**成功标准**

- 类清单与分层依赖满足 `be-class` 验收条款；每条主路径至少一条时序；可选要素（导出/调度/分布式事务/BPM）在 PRD 无诉求时明确「不适用」。

## 执行步骤

1. **`[自动]`**：四层类矩阵 + 受影响文件清单。
2. **`[自动]`**：核心用例流程图与时序。
3. **`[自动]`**：按需章节（事务、导出、JOB、审批）。
4. **`[交互]`**：对跨服务耦合与兜底策略与用户确认。

### incremental 模式

**Step 1:** `[自动]` 读取基线 backend.md，定位受影响的核心类/时序/事务/定时任务/审批流章节，
提取 baseline_state。

**Step 2:** `[自动]` 对 element_changes 中每个变化点，生成 DELTA 块和 DIP，遵循以下约束：

| 子域 | 增量核心动作 | 强制边界约束 |
|------|------------|------------|
| 核心代码类 | 新增类或扩展方法 | **既有接口签名禁止修改** |
| 处理逻辑时序 | 新增/调整时序节点和调用链 | **既有 Happy Path 禁止删除** |
| 分布式事务 | 新增事务场景或调整回滚策略 | — |
| 数据导出 | 新增/调整导出方案 | — |
| 定时任务 | 新增/调整任务配置 | 须明确 Cron 表达式、批处理阈值 |
| 审批流配置 | 新增/调整审批节点和策略 | — |

**Step 3:** `[交互]` 若涉及以下情形须暂停确认：
- 存量类的方法签名变更
- 状态流转调整影响已上线业务
- 定时任务的"上级"查询逻辑或重试策略不明确
