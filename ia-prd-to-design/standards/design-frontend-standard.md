### 一级目录与外部注册

- **必须**：每个页面对应 **唯一一级目录名**（路径表现为单层，例如 `/tag-management`）。
- **禁止**：**二级路由路径**（例如 ~~`/tag-management/maintain`~~）；不得以嵌套路由表达子页面。
- **声明范围**：技术方案中**只声明目录名与业务含义**，**不写** `router` 配置代码；**目录创建与路由注册在外部系统完成**，方案中忽略注册实现。
- **详情 / 子状态**：通过 **Query** 传参（如 `id`），或通过父页面内状态切换；**禁止**用额外路径段表达。
- **弹窗 / 对话框**：**不需要路由**；在父页面通过 **visibility**（显隐）控制。

### 命名建议

- 目录名：小写、连字符，与业务含义一致（如 `tag-management`、`resource-detail`）。

# 页面级组件与字段规范 — **组件与字段**（新增侧）（§4.3）

对应业务要素 **「组件与字段」** 中需**新建或实质性改造**的业务组件：组件树、Props/Emits/Slots，以及 **表格列 / 表单字段 / 枚举** 等结构化字段定义。

## 组件类型定义

| 类型      | 职责                                           | 是否有状态 | 是否调用 API |
| --------- | ---------------------------------------------- | ---------- | ------------ |
| Page      | 路由入口，组合 Container，处理页面级生命周期   | 是         | 否           |
| Container | 数据获取和状态管理，向子组件分发数据           | 是         | 是           |
| Component | 纯展示/交互，通过 Props 接收数据，emit 事件    | 否（或局部） | 否         |

## 拆分原则

- **单一职责**：一个组件只做一件事
- **100行原则**：组件模板超过 100 行考虑拆分
- **复用优先**：超过 2 处相似 UI 必须抽取为公共组件
- **避免深层 Props Drilling**：超过 3 层透传改用 provide/inject 或 Store

## 命名规范

- 组件文件名：大驼峰，`OrderList.vue`、`OrderDetailCard.vue`
- 目录结构：`src/pages/{模块}/components/{组件名}.vue`
- 公共组件放 `src/components/`

## Props 设计

- Props 类型必须明确声明（TypeScript interface 或 defineProps withDefaults）
- 复杂对象 Props 定义独立的 TypeScript interface
- Props 只传必要的数据，不传整个对象再在子组件里取字段

## 组件通信

| 场景                         | 方案                    |
| ---------------------------- | ----------------------- |
| 父 → 子                      | Props                   |
| 子 → 父                      | Emit                    |
| 跨层级（祖 → 孙）            | provide/inject          |
| 跨组件树（兄弟、远亲）       | Pinia Store             |
| 页面间传递复杂数据           | Pinia Store（不用路由大量传参） |

## 组件类型与拆分

| 类型 | 职责 | 状态 | 调 API |
| ---- | ---- | ---- | ------ |

- Props 类型须明确；勿深层透传超过 3 层（改用 provide/inject 或 Store）。

## 状态存放

| 条件 | 位置 |
| ---- | ---- |
| 单组件内 | `ref` / `reactive`（自 `vue-demi`） |
| 同页多组件 | 父 State + Props |
| 跨页或持久 | Pinia 等 Store |
| 可分享/回退保留 | URL Query（一级路径不变） |

Store 命名惯例：`loading`、`submitting`；离开页面按需 reset（按工程惯例）。

---

## 反馈与表单

- 操作须有即时反馈；长耗时 Loading。
- **禁止**原生 `alert` / `confirm` / `prompt`；二次确认与提示使用 **脚手架提供的对话框 / Message**（与「编码约束」一致）。
- **弹窗 / 抽屉**：不占路由，在父页面用 **visibility** 控制显隐。
- 表单：必填标识、校验时机、脏数据离开提示。

- 前端承担展示与体验层校验；**不替代**后端强校验。
