# 去噪清理流程（L4 两轮清理）

> 本文档详细描述 L4 阶段的执行步骤。去噪规则字典见 [reference/denoise-rules.md](../reference/denoise-rules.md)。

## L4-0 无效信息识别

**目标**：识别转换产物中的无效信息（装饰性图片、封面模板、空表格等）。

> 完整去噪规则（含设计文档专用规则）见 [reference/denoise-rules.md](../reference/denoise-rules.md)。

### 无效信息分类

| 类别 | 识别方法 | 典型特征 |
|------|---------|---------|
| **装饰性图片** | 图片类型黑名单匹配 | 品牌 Logo、角色图标、装饰插画 |
| **封面页模板** | 多行特征正则匹配 | 版权声明、公司地址、联系方式 |
| **空模板表格** | 正则匹配空行 | 所有单元格均为空的表格行 |
| **模板控制章节** | 固定文本匹配 | "文版模板控制"、"文档内容控制" |
| **修订/批注残留** | XML 标记检测 | `<w:ins>`、`<w:del>`、批注引用 |
| **水印/页眉页脚** | 位置+重复度检测 | 每页重复出现的页眉页脚文本 |

### 预应用学习闭环规则

> 若 `{output_dir}/_audit/memory/findings.json` 存在，先加载已积累的规则（见 [reference/learning-loop.md](../reference/learning-loop.md)），预标记已知模式的无效信息。

### 识别报告

```
无效信息识别结果：
- 装饰性图片: 127 张（5.1%）
- 封面页模板: 6 个文件
- 空表格行: 576 行
- 模板章节: 6 处
- 修订残留: 3 处
- 水印/页眉页脚: 12 处
```

**产出**：无效信息清单（类型、数量、位置）。

## L4-1 第一轮无效信息清理（并行 SubAgent）

**目标**：使用 `parallel_count` 个并行 SubAgent 清理识别出的无效信息。

### 并发策略

按文件大小 round-robin 分配到 N 组，每个 SubAgent 处理一组文件。

### SubAgent 任务

使用 [templates/subagent-cleanup.md](../templates/subagent-cleanup.md) 模板启动清理 SubAgent。

### 清理规则摘要

1. **装饰性图片清理**：匹配黑名单 → 删除整段图片说明块（7行）+ 图片引用行
2. **封面页模板清理**：同时满足 3 项以上特征 → 删除从开头到"目 录"之间的封面块
3. **空表格行清理**：所有单元格为空的行删除，保留表头和分隔线，保留含"示例"字样的行
4. **模板章节清理**：匹配模板控制章节 → 删除整个章节
5. **修订/批注清理**：接受所有修订、删除批注标记
6. **水印/页眉页脚清理**：删除每页重复出现的非业务文本

> 完整规则定义见 [reference/denoise-rules.md](../reference/denoise-rules.md)。

### 保守原则

- 不确定时保留内容
- 仅删除明确匹配规则的内容
- 记录所有删除操作到清理报告

### 清理报告格式

```json
{
  "file": "文件名.md",
  "removed_images": 15,
  "removed_cover_pages": 1,
  "removed_empty_rows": 23,
  "removed_template_sections": 0,
  "removed_revisions": 2,
  "removed_headers_footers": 4,
  "removed_lines": 156,
  "details": [...]
}
```

**产出**：清理后的 MD 文件 + N 个清理报告（JSON）。

## L4-2 第一轮清理审计（独立第三方）

**目标**：使用独立 SubAgent 验证第一轮清理质量。

### 审计维度

1. **装饰性图片残留**：是否还有黑名单图片类型；是否有孤立图片说明块
2. **封面页残留**：是否还有封面页特征文本
3. **空表格行残留**：是否还有全空行（注意区分业务表格子项目行）
4. **模板章节残留**：是否还有模板控制章节
5. **业务内容保护**：抽样确认业务内容未被误删；图片引用一致性；JSON 映射完整性

**产出**：第一轮清理审计报告（残留问题清单）。

---

## L4-3 第二轮无效信息清理（处理残留）

**目标**：根据第一轮审计结果，清理残留的无效信息。

### 扩展黑名单（第二轮新增）

第一轮审计发现的遗漏类型，自动加入 `findings.json` 供后续复用：

```python
ROUND2_ADDITIONS = [
    "纯白空白图",      # 纯白背景的空白图
    "PPT分隔页",       # PPT 章节分隔页
    "表格边框",        # 仅显示表格边框的截图
    "√对勾截图",       # 环境定义表中的对勾标记
]
```

### 增强清理规则

- **孤立图片说明块清理**：删除没有对应图片引用的说明块（有 `> **【图片说明】**` 但无 `![图片IMG-xxx](...)`）
- **边界案例**：纯白空白图、PPT 分隔页、表格边框截图、√对勾截图 → 删除

### 保守原则（强化）

- 业务表格的子项目行（部分列为空但含业务数据）不是无效信息，保留
- 不确定时保留内容
- 记录所有删除操作

**产出**：二次清理后的 MD 文件 + N 个清理报告。

---

## L4-4 临时文件清理

**目标**：清理处理过程中产生的临时文件。

1. 删除清理报告 JSON 文件（`cleanup_group_*_report.json`、`cleanup2_group_*_report.json`）
2. 删除分组文件列表（`group_*_files.json`）
3. 删除临时 Python 脚本（如有）
4. 验证只保留最终产物（MD + JSON + images/ + _audit/）

**产出**：清理后的目录结构（仅最终产物）。

## 常见问题

### 空表格行误判

**问题**：业务表格的子项目行被误判为空行并删除。

**解决**：区分"所有单元格均为空"和"部分列为空但含业务数据"。业务表格子项目行（继承父行分类列的子行）应保留。在清理 SubAgent 指令中明确此区别。

### 装饰性图片误删业务图片

**问题**：黑名单匹配过于宽泛，误删含业务语义的图片。

**解决**：保守原则——不确定时保留；仅删除图片类型明确匹配黑名单的；"其他"类图片需人工复核，不自动删除。
