# Office文档多模态转换与清理技能

## Pilot 协作（standalone 直驱，不经内核）

- 本 skill 为 standalone 直驱，不经 Pilot 协议分发，不调用 `pilot_handoff` / `pilot_advance` / `pilot_checkpoint`
- 产物为结构化 Markdown + JSON 映射文件，供下游知识库构建（`iscit-klBuild-init`）或需求分析消费

## When to Use

| 场景 | 触发方式 |
|------|---------|
| 批量转换Office文档为Markdown | `/iscit-doc-converter` 或用户提及"文档转换" |
| 清理已转换MD中的无效信息 | 用户提及"无效信息清理"、"装饰性图片清理" |
| 评估转换质量 | 用户提及"转换质量评估"、"审计" |

## Inputs

| 参数 | 必填 | 说明 | 示例 |
|------|------|------|------|
| `source_dir` | 是 | 源文件目录路径 | `docs/原始设计方案/` |
| `output_dir` | 否 | 输出目录（默认 `{source_dir}md/`） | `docs/原始设计方案md/` |
| `parallel_count` | 否 | 并行SubAgent数量（默认6） | `6` |
| `cleanup_mode` | 否 | 是否执行无效信息清理（默认true） | `true` / `false` |
| `audit_mode` | 否 | 是否执行独立审计（默认true） | `true` / `false` |

## Checkpoints

- **L1完成后**：输出源文件清单与格式分布，无需用户确认即进入L2
- **L2完成后**：输出转换统计报告，进入L3审计
- **L3完成后**：输出质量审计报告，如有问题则进入L4清理
- **L4完成后**：输出清理统计与最终质量评级

## Workflow

### L1-0 源文件扫描与分组

**目标**：扫描源目录，识别文件格式，按格式分组。

**步骤**：

1. 扫描 `source_dir` 下所有文件，按扩展名分类：
   - PPTX（演示文稿）
   - DOCX（Word文档）
   - XLSX（Excel表格）
   - PDF（PDF文档）
   - JPG/PNG（图片文件）

2. 生成源文件清单，统计各格式文件数：
   ```
   源文件统计：
   - PPTX: 85 个
   - XLSX: 40 个
   - DOCX: 4 个
   - PDF: 4 个
   - JPG: 1 个
   总计: 134 个文件
   ```

3. 为每个文件分配唯一ID（基于文件名stem），用于后续追踪。

**产出**：源文件清单（格式、数量、文件大小）。

---

### L1-1 输出目录准备

**目标**：创建输出目录结构。

**步骤**：

1. 创建 `output_dir`（如不存在）
2. 创建 `output_dir/images/` 子目录（存放提取的图片）
3. 验证目录可写权限

**产出**：输出目录结构就绪。

---

### L2-0 并行多模态转换（核心步骤）

**目标**：使用并行SubAgent将每个源文件转换为结构化Markdown + JSON映射。

**并发策略**：
- 默认启动 **6个并行SubAgent**
- 按文件大小 round-robin 分配到6组，确保负载均衡
- 每个SubAgent处理一组文件（约22-23个文件）

**SubAgent任务描述模板**：

```
你是文档转换专家。请将以下文件转换为结构化Markdown格式。

## 输入文件
{file_list}

## 输出要求

### 1. Markdown文件（{filename}.md）

#### 文本提取
- 保留原文层级结构（标题、段落、列表）
- 表格转换为Markdown表格格式
- 保留表格合并单元格信息（用文字说明）

#### 图片处理（5维描述格式）
对每张提取的图片，生成结构化描述块：

> **【图片说明】**
> - **图片类型**：{原型界面截图|业务流程图|表格截图|系统架构图|数据流图|...}
> - **图片标题**：{图片标题或"无"}
> - **详细描述**：{图片内容的详细文字描述}
> - **关键要素清单**：{图中关键元素列举}
> - **流程/逻辑说明**：{业务流程或逻辑关系说明}
> - **源文档位置**：第{N}页幻灯片
> - **图片编号**：IMG-{XXX}

图片引用格式：`![图片IMG-XXX](images/{source_stem}_p{NN}_{MM}.png)`

#### 特殊内容处理
- PPT备注：转换为"备注"段落
- SmartArt/图表：提取为图片 + 5维描述
- 合并单元格：用文字说明合并关系

### 2. JSON映射文件（{filename}_映射数据.json）

```json
{
  "file_info": {
    "source_filename": "原始文件名.pptx",
    "source_format": "pptx",
    "page_count": 45,
    "image_count": 18,
    "table_count": 12,
    "word_count": 5234
  },
  "content_mapping": [
    {
      "md_location": "第15-18行",
      "source_location": "第3页幻灯片",
      "content_summary": "系统架构图及说明",
      "source_type": "image",
      "action": "extracted",
      "remark": "5维描述完成"
    }
  ],
  "template_removed": [],
  "exceptions": []
}
```

### 3. 图片文件
- 提取所有图片到 `images/` 目录
- 命名格式：`{source_stem}_p{page}_{seq}.png`
- 使用WPS渲染提取（捕获SmartArt、组合形状等API遗漏的图片）

## 质量控制
- 每张图片必须有完整的5维描述
- 不允许出现 `[待SubAgent补充]` 占位符
- JSON映射必须覆盖所有内容块
- 表格必须保留在原文上下文中（不 detach 到末尾）

## 保守原则
- 不确定是否为业务内容时，保留
- 宁可漏删不可误删
- 记录所有异常情况到 `exceptions` 字段
```

**SubAgent执行**：

```python
# 伪代码：并行SubAgent调度
groups = distribute_files_round_robin(file_list, group_count=6)
for i, group in enumerate(groups):
    launch_subagent(
        task=f"转换文件组 {i+1}",
        files=group,
        output_dir=output_dir,
        instructions=SUBAGENT_TEMPLATE
    )
wait_for_all_subagents()
```

**产出**：
- N 个 Markdown 文件
- N 个 JSON 映射文件
- M 个图片文件（`images/` 目录）

### L2-1 转换完整性检查

**目标**：验证所有文件转换完成，无遗漏。

**步骤**：

1. 检查每个源文件是否都有对应的 `.md` 和 `_映射数据.json`
2. 检查所有图片引用是否都有对应文件
3. 检查是否有 `[待SubAgent补充]` 占位符残留
4. 统计转换结果：
   ```
   转换完成统计：
   - 源文件: 135 个
   - MD文件: 135 个 ✓
   - JSON映射: 135 个 ✓
   - 图片文件: 2,483 个
   - 图片引用: 2,478 条
   - 孤立图片: 5 个（存在于images/但未被引用）
   ```

**产出**：转换完整性报告。

### L3-0 独立质量审计（第三方视角）

**目标**：使用独立SubAgent验证转换质量，不依赖转换SubAgent的自报告。

**审计SubAgent任务描述**：

```
你是独立第三方审计专家。请验证文档转换质量。

## 审计范围
- 源文件目录：{source_dir}
- 转换产物目录：{output_dir}

## 审计维度

### 1. 零丢失验证
- 对比源文件API提取的内容 vs JSON映射记录
- 对比JSON映射记录 vs MD文件内容
- 检查是否有内容块被遗漏

### 2. 图片完整性验证
- 检查每张图片引用是否都有对应文件
- 检查每个5维描述块是否完整（5个字段都有值）
- 统计图片类型分布

### 3. 表格完整性验证
- 检查表格是否保留在原文上下文中
- 检查表格行数和列数是否与源文件一致
- 检查是否有空表格或损坏表格

### 4. 结构完整性验证
- 检查标题层级是否正确
- 检查段落顺序是否与源文件一致
- 检查是否有内容错位

### 5. JSON映射完整性验证
- 检查每个JSON文件的 `content_mapping` 是否覆盖所有内容块
- 检查 `md_location` 和 `source_location` 是否准确
- 检查 `exceptions` 字段是否记录了所有异常

## 输出要求
生成审计报告，包含：
- 各维度的通过率
- 发现的问题清单（如有）
- 总体质量评级（A/B/C/D）
- 改进建议
```

**审计执行**：

```python
# 启动独立审计SubAgent
launch_subagent(
    task="独立质量审计",
    source_dir=source_dir,
    output_dir=output_dir,
    instructions=AUDIT_TEMPLATE
)
```

**产出**：独立审计报告（质量评级、问题清单）。

### L4-1 第一轮无效信息清理（并行SubAgent）

**目标**：使用6个并行SubAgent清理识别出的无效信息。

**并发策略**：
- 按文件大小 round-robin 分配到6组
- 每个SubAgent处理一组文件（约22-23个文件）

**清理SubAgent任务描述模板**：

```
你是文档清理专家。请清理以下文件中的无效信息。

## 输入文件
{file_list}

## 清理规则

### 1. 装饰性图片清理
- 匹配图片类型黑名单（见下方列表）
- 删除整段图片说明块（7行）+ 图片引用行
- 图片说明块格式：从 `> **【图片说明】**` 到 `> - **图片编号**：IMG-xxx`

### 2. 封面页模板清理
- 匹配封面页特征（同时满足3项以上）
- 删除从文件开头到"目 录"之间的封面页块

### 3. 空表格行清理
- 匹配所有单元格均为空的表格行
- 删除空行，保留表头和分隔线
- 保留含"示例"字样的行

### 4. 模板章节清理
- 匹配模板控制章节
- 删除整个章节（从章节标题到下一同级标题）

## 图片类型黑名单
{INVALID_IMAGE_TYPES列表}

## 保守原则
- 不确定时保留内容
- 仅删除明确匹配规则的内容
- 记录所有删除操作到清理报告

## 输出要求
生成清理报告（JSON格式）：
{
  "file": "文件名.md",
  "removed_images": 15,
  "removed_cover_pages": 1,
  "removed_empty_rows": 23,
  "removed_template_sections": 0,
  "removed_lines": 156,
  "details": [...]
}
```

**清理执行**：

```python
# 并行清理SubAgent调度
groups = distribute_files_round_robin(file_list, group_count=6)
cleanup_reports = []
for i, group in enumerate(groups):
    report = launch_subagent(
        task=f"清理文件组 {i+1}",
        files=group,
        instructions=CLEANUP_TEMPLATE
    )
    cleanup_reports.append(report)
wait_for_all_subagents()
```

**产出**：
- 清理后的MD文件
- 6个清理报告（JSON格式）

## 输出要求

- 各类无效信息的残留数量

## 附录B：并行SubAgent调度策略

### Round-Robin分组算法

```python
def distribute_files_round_robin(files, group_count=6):
    """按文件大小排序后round-robin分配到N组"""
    # 按文件大小降序排序
    sorted_files = sorted(files, key=lambda f: os.path.getsize(f), reverse=True)
    
    # 初始化N个空组
    groups = [[] for _ in range(group_count)]
    
    # Round-robin分配
    for i, file in enumerate(sorted_files):
        group_idx = i % group_count
        groups[group_idx].append(file)
    
    return groups
```

### SubAgent并发控制

| 并发数 | 适用场景 | 说明 |
|--------|---------|------|
| 6 | 文件编辑任务（默认） | 平衡并发与资源占用 |
| 3-4 | 重度代码读取任务 | 避免上下文溢出 |
| 2 | 超大文件处理 | 单文件处理时间长 |

### SubAgent错误处理

```python
# SubAgent失败时的重试策略
def handle_subagent_failure(subagent_result):
    if subagent_result.status == "failed":
        # 记录错误日志
        log_error(subagent_result.error)
        
        # 提取已完成的文件列表
        completed_files = subagent_result.completed_files
        
        # 重新启动SubAgent处理剩余文件
        remaining_files = subagent_result.assigned_files - completed_files
        if remaining_files:
            retry_subagent(remaining_files)
```

## 附录D：常见问题与解决方案

### Q1: SubAgent处理大文件时超时

**问题**：单个文件超过100页，SubAgent处理时间过长导致超时。

**解决方案**：
- 将大文件拆分为多个批次（每50页一批）
- 增加SubAgent超时时间（默认30分钟 → 60分钟）
- 使用2-3个并发（而非6个）处理大文件

### Q2: 图片提取失败

**问题**：某些SmartArt或组合形状无法通过API提取。

**解决方案**：
- 使用WPS渲染提取（捕获API遗漏的图片）
- 记录异常到JSON的 `exceptions` 字段
- 在MD中保留占位符说明（如"此处有SmartArt图表，无法提取"）

### Q3: 表格上下文丢失

**问题**：表格被detach到文档末尾，失去上下文。

**解决方案**：
- 在转换SubAgent的指令中明确要求"表格必须保留在原文上下文中"
- 审计时检查表格位置是否与源文件一致
- 如发现detach，启动修复SubAgent重新定位表格

### Q4: 空表格行误判

**问题**：业务表格的子项目行被误判为空行并删除。

**解决方案**：
- 区分"所有单元格均为空"和"部分列为空但含业务数据"
- 业务表格的子项目行（如继承父行分类列的子行）应保留
- 在清理SubAgent指令中明确说明此区别

### Q5: 装饰性图片误删业务图片

**问题**：黑名单匹配过于宽泛，误删了含业务语义的图片。

**解决方案**：
- 保守原则：不确定时保留
- 仅删除图片类型明确匹配黑名单的
- "其他"类图片需人工复核，不自动删除
- 审计时检查业务内容保护情况
