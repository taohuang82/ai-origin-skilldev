## 10. 变化点 → 要素影响映射(完整)

每个变化点 = **直接命中(变化源)** + **关系闭包命中(下游)**。下游命中**永远沿关系算**,不写死实例:runtime 用 `cross-references.yaml` 反查"谁引用了变化源",得到具体实例;本节只规定"沿哪条关系、定哪个档"。

**三种依据类型(每条命中必须标注)**:
- **关系反查**:变化源被命中要素的正向关系属性引用,可在 cross-references 反向索引算出实例。反查路径写 `命中要素.属性`(单跳)或 `A.属性 → B.属性`(多跳链式),每跳标 §5 关系编号。
- **关系顺查(依赖协变)**:变化源正向 uses/depends_on 命中要素,变化时要求被依赖方协变(如 API 契约变 → 其依赖的 AS/DS 协变)。confidence 统一 conditional。
- **语义推断**:§5 无关系边支撑,基于业务常识推断。confidence 必为 conditional,且必须给 condition;不得冒充关系反查。

**三级置信度**:certain(自动入)/likely(默认入可跳)/conditional(按 condition 或人确认)。

> **中心节点充分扩散原则**:SubFeature / Aggregate / BusinessProcess / BusinessRule / Role 是高连接度节点,变化时必须沿 §5 存在的关系边把 Scenario / Feature / Domain 等下游全部展开,不得漏。测试相关命中(TestCase/TestData)本阶段不纳入,作为可配置元数据待 ia-test-design 启用(见 §7.25 说明)。

```yaml
change_element_mappings:
  - change_id: DA-01
    name: 实体/聚合根加改字段

      - { element_type: DomainService, action: modify, confidence: conditional,
          basis: 关系反查, reverse_via: "collaborates_with_entities" }
      - { element_type: ValueObject, action: create, confidence: conditional,

      - { element_type: Integration, action: create, confidence: conditional,

      - { element_type: BusinessRule, action: create, confidence: conditional,
          basis: 语义推断, condition: 新字段带来新约束 }
```

**关键约定**:`closure_hits[].basis` 三选一(关系反查/关系顺查/语义推断);`reverse_via` 存反查属性名(非实例 id),runtime 用 cross-references 查"谁的该属性指向变化源";语义推断项无 reverse_via 但必带 condition。静态档位规则与动态反查彻底分离。
## 11. 影响闭包算法(沿单端关系图)

```python
def analyze_impact(rr, user_changes, asset_lib):
    effective = {rr.id: ("create","certain","RQ-01")}        # always RR
    atomic = identify_changes(user_changes)                  # 匹配 23 变化点;低置信度→暂停澄清
    # 直接命中
    for ac in atomic:
        for hit in mapping[ac.id].direct_hit:
            effective[resolve_instance(ac, hit, asset_lib)] = (hit.action, "certain", ac.id)
    # 关系闭包(沿 cross-references 反查)
    queue = list(effective)
    while queue:
        x = queue.pop()
        for ch in changes_whose_source_is(x):
            for rule in mapping[ch].closure_hits:
                for y in cross_refs.reverse_lookup(x, rule.reverse_via):   # 谁的属性指向 x
                    if rule.conf=="conditional" and not check(rule,y): ask_user(y,rule); continue
                    if y not in effective or higher(rule.conf, effective[y][1]):
                        effective[y] = (rule.action, rule.conf, ch); queue.append(y)
    # always
    if any_domain_or_feature_change(effective):
        effective[PRODUCT_OVERVIEW] = ("modify","certain","always")
    return effective
```

**收敛性**:关系单端、依赖无环 → 反向闭包是 DAG 可达集计算,必终止。**无漏**:reverse_lookup 基于最新 cross-references。**无冗**:单端存储,不重复入集。

## 15. 共享元模型 + 数据流

**0→1 数据流**:
```
fe-gen(build)→FE文档 → fe-to-prd(build)→PRD文档 → prd-to-design(build)→TDD文档
        ↓ 四份文档齐备、各级人确认
asset-mgmt: extract-doc → 抽取清单 → merge(全 create)→ 资产库 V0 + cross-references 首建
```

**1→n 数据流**:
```
新 RR → asset-mgmt:render → 现状视图
     → 文档 Skill(incremental):输入=现状视图+RR+人确认变化点
        → L3.5 变化点路由(可调 o-asset-analyze 算闭包)→ 只产命中要素 DELTA
     ↓ 各级人确认
asset-mgmt: extract-doc(只抽 DELTA 节)→ merge(create/modify/deprecate + 字段级合并 + 冲突裁决)
        → 资产库 V(n) + cross-references 重建 + 归档
```

> **影响分析归属**:重闭包走 ia-asset-mgmt.o-asset-analyze;文档 Skill 加载同一份 change-element-mapping 做轻判定(本要素该不该产增量)。同一份数据,结果一致,逻辑不两处维护。

## 16. L5 规格三处一致性校验(自检清单)

后续展开各要素 L5 时,必须保证三处属性名一致:
- **第 5 节关系总表**的"源端属性" = **第三部分要素卡 YAML**的字段名 = **第 10 节映射**的 `reverse_via`。
- 任一处改属性名,三处同步改;共享元模型 `relations.yaml` 是唯一权威。
