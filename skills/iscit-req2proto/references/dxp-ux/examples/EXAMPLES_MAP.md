# 需求 → 结构样例路由（iscit-req2proto）

> 目的：用户自然语言描述与 `examples/` 下页面形态对齐，避免模型随机选错参考或忽略样例。  
> 生成前 **必须** 按本节选定 **恰好 1 个** 最贴近目录，并 Read 该目录下的 `index.html` 与 `styles.css`（分文件仅作结构参考，最终仍输出单文件内联 HTML，见主 SKILL Step 4）。  
> **全局约定**（定位 skill、禁止在用户工程找案例、读写边界）以主 `SKILL.md` 的 **「执行总则」** 为准；本节专注 **路由与 list-page 四层列表模式**。

## 路径说明（与主 SKILL「执行总则」一致）

所有路径均相对于 **iscit-req2proto skill 根目录** `<iscit-req2proto>`（含主 `SKILL.md` 的目录），**不得**从用户业务工程根目录解析。定位方式：Glob `**/iscit-req2proto/SKILL.md`，其所在目录即 `<iscit-req2proto>`；若在 ISC-Q 仓库内，也可用 `skills/iscit-req2proto/...`（从仓库根起）。

## 选用流程（执行顺序）

1. 根据用户描述判断 **tp / ap**（与主流程 Step 1 一致）。
2. 从下方「关键词 → 目录」表中命中 **第一条最具体的匹配**；若无命中，使用 **默认回退**。
3. 用 Read 读取：`<iscit-req2proto>/references/dxp-ux/examples/<目录>/index.html` 与同目录下的 `styles.css`。
4. 提炼：页面壳（`ux-page` / 侧栏+主区）、页头、卡片分区、表格工具栏、分页、Modal/Drawer 是否出现。
5. 将上述结构 **映射** 到输出：优先复用 `ux-*` 语义与分区顺序；与 [components.md](../components.md) 冲突时以 **components + rules** 为准。
6. 若用户需求明确 **不包含** 该样例的典型能力（例如无地图），勿照搬整页，只借用布局与组件组合方式。

## 与 `tp-ux` 的分工（交易类列表）

若页面为 **独立「查询条件」多列表单栅格 + 数据表**，且表格列要求为 **左侧：序号 → 多选/单选 → 操作 → 业务数据**（典型 ERP / TP），**不要**选用本目录的 **`list-page`** 作为主结构样例；应 Read **`<iscit-req2proto>/references/tp-ux/examples/EXAMPLES_MAP.md`** 并选用 **`list-query-table-page`**。  
**仅当**需要 **DXP 四层**（顶栏批量操作 → **单行**筛选含设置 → 表体 → 分页）时，才选用下方 **`list-page`**。

## `list-page` 专区：四层列表模式（匹配到本样例时强制）

当选定 **`list-page`** 时，列表页 **默认只能** 采用本节 **四层** 骨架；各层可按需求删减控件数量，但 **四层容器与纵向顺序不得合并或打乱**（与 `list-page/index.html` 一致）。**禁止**改用「单卡片内无分区大杂烩」等非本模式布局。

### 自上而下顺序（四层 + 可选 Tab）

| 层 | 用户称谓 | 样例/DOM 约定 | 职责与边界 |
|----|----------|---------------|------------|
| 0 | （可选）视图/统计 | `nav.ux-tabs` | 多视图、统计 Tab；无需求可省略整段 |
| **1** | **顶部操作列** | `div.ux-toolbar`（`aria-label` 含「工具栏」） | 新建、导出、批量、关闭等业务主操作；**不得**在本层放表格分页、不得放表体筛选表单（仅放操作按钮） |
| **2** | **筛选区** | `section.ux-searchRow`（或等价独立 `section`，`aria-label` 含「搜索」或「筛选」） | 综合搜索、高级搜索、筛选项（下拉/日期等）；**设置类 icon 按钮必须在本层**（样例为 `button.ux-iconBtn` `aria-label="设置"`），**禁止**把设置挪到表头替代本区 |
| **3** | **表格内容区** | `section.ux-tableBlock` 内 **`ux-tableWrap` + `table.ux-table` 仅表头与数据行** | 仅数据表格与横向滚动容器；**禁止**在本层 DOM 内夹入分页控件（页码、每页条数等） |
| **4** | **底部 pager 区** | 同一 `section.ux-tableBlock` 内紧随表体下方的 **`div.ux-tableFooter`**（左摘要 + 右 `div.ux-pagination`） | 总条数、已选、每页条数、页码、跳转等；**必须**独立在表体之下，**禁止**挪到顶栏或筛选行 |

> **DOM 提示**：样例将第 3、4 层都放在 `ux-tableBlock` 内，逻辑上仍为 **表体 / 分页** 两段；生成单文件原型时保持相同 **视觉与语义顺序** 即可。

### 按需裁剪

- 无多视图：省略 **层 0**。
- 筛选项少：**层 2** 仍保留独立容器（至少一行综合搜索或筛选项）；**有列设置/视图设置需求时，设置 icon 必须在本层**；无该需求时可省略设置按钮，**不得**把设置挪到表头凑数。
- 无分页数据：**层 4** 仍保留分页条容器结构（可禁用或展示 0 条），以符合 DXP 表格默认能力约定。

### 验收要点

- [ ] **层 1** 顶栏操作列单独成行，在筛选区之上。
- [ ] **层 2** 筛选区单独成行；**设置 icon 位于本层**，不在表头。
- [ ] **层 3** 仅表体（`thead`/`tbody`），无分页控件。
- [ ] **层 4** 底部分页区在表体之下，含分页与条数摘要。
- [ ] 使用 `tv-*` 映射时，仍须 **四段顺序** 等价落地，不得把分页与筛选挤在同一行。

## 与 isc-scenarios 的对应（辅助推断）

结合 [isc-scenarios.md](../../isc-scenarios.md)：

- 场景 1–7（采购/销售/库存/物流单证/供应商/计划/质检）以 **表格操作为主** → 默认 **`list-page`**；若强调「层级物料/分类树」→ **`tree-table-page`**。
- 场景 8（全球运输监控）→ **`logistics-map-page`**。
- 场景 9–12（库存/供应商/采购/生产分析看板）→ 若强调 **多 KPI + 图表栅格** → **`overview-page`**；若与模板 `template-ap.html` 更接近大屏，则以 **ap 模板** 为主，**仅从 overview 样例借鉴卡片栅格与间距**。
- **待办/审批队列** → **`todo-task-page`**。

## 默认回退

- **交易类 (tp)**：未命中上表任何关键词时，使用 **`list-page`**（最通用的列表+筛选+表结构）。
- **分析类 (ap)**：优先 Read `<iscit-req2proto>/assets/template-ap.html`；若需浅色 KPI 总览，可额外参考 **`overview-page`** 的卡片布局，再按 ap 深色规范改色。

## 禁止

- 禁止在未 Read 选定目录下 `index.html` / `styles.css` 的情况下声称已「参考 examples」。
- 禁止把 **分文件示例** 原样当作最终交付物路径；交付物始终是 **用户工程** 下 **`output/proto-*.html` 单文件**。
- 禁止仅用 `assets/...` 或 `references/...` 相对路径在 **用户业务工程** 内查找 skill 模板（会 File not found）；必须先解析 `<iscit-req2proto>`。
- 禁止在 **用户项目** 内 Glob 诸如 `**/examples/**`、`list-page` 等并当作本技能案例——用户仓库的 examples 与本 skill 无关；**dxp-ux** 案例仅来自 `<iscit-req2proto>/references/dxp-ux/examples/`；**TP 查询+左序表** 案例来自 `<iscit-req2proto>/references/tp-ux/examples/`。
