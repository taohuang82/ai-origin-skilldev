# fe-interaction-logic 设计规范

> 本要素已整合原 `fe-state`（状态管理）子要素，`fe-state` 作为 alias 路由至本要素。状态管理作为 §4.6 内部子分段输出，不再单独成节。

## 适用条件

- PRD 包含用户操作流程、表单提交、弹窗、抽屉、二次确认、批量操作、异常反馈或复杂交互。
- 状态模型、跨组件状态、持久化状态、URL Query 状态。

## 前置依赖

- `fe-page-structure`
- `fe-component`
- `fe-api-binding`

## 输出归属

- 聚合到 `{DESIGN_DIR}/frontend.md` 的 `## §4.6 交互逻辑`
- 状态管理内容作为 §4.6 内部子分段（状态设计、影响范围）输出，不再使用独立标题 `## §4.6 交互逻辑（状态管理）`。

## 执行步骤

### build 模式

1. 识别需要状态管理的场景（单组件内、同页多组件、跨页持久、URL Query）。
2. 为每个场景明确状态变量类型、存放位置、初始化方式和重置时机。
3. 识别关键用户操作场景。
4. 为每个场景描述触发方式、前置条件、有序步骤、参数组装、成功反馈、失败反馈。
5. 明确表单校验、二次确认、弹窗/抽屉显隐、重复提交控制和异常状态。
6. 与 `fe-api-binding` 对齐，避免状态变量和接口链路矛盾。

### modify 模式

1. 仅修改命中交互场景与命中状态模块。
2. 保留未命中的交互规则与状态定义。

### incremental 模式

1. Read 基线 `§4.6`。
2. 仅对新增或变化交互、新增或变化状态写 DELTA。

**增量边界**：交互场景 | 操作链路 | 反馈规则 | 表单体验 | 异常处理 | 状态变量 | 存放位置 | 类型 | 持久化兼容

## 质量检查点

- 每个关键操作均包含触发方式、前置条件、有序步骤、成功反馈、失败反馈。
- 表单、弹窗、抽屉、二次确认和失败反馈有明确边界。
- 不使用原生 `alert` / `confirm` / `prompt`。
- 与 `fe-api-binding` 的接口数据一致、接口触发时机一致。
- 状态变量与交互所需状态对齐；不展开完整操作流程与状态定义的重复内容。
- 无循环依赖。
- 分节标题字面量 `## §4.6 交互逻辑`。
- 无占位符、空 Mermaid、空表头。
- 符合 `standards/frontend/fe-interaction-logic.md`。
