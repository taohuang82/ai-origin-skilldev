# 页面级组件与字段规范 — **组件与字段**（新增侧）（§4.3）

对应业务要素 **「组件与字段」** 中需**新建或实质性改造**的业务组件：组件树、Props/Emits/Slots，以及 **表格列 / 表单字段 / 枚举** 等结构化字段定义。

## 组件类型定义

| 类型      | 职责                                           | 是否有状态 | 是否调用 API |
| --------- | ---------------------------------------------- | ---------- | ------------ |
| Page      | 路由入口，组合 Container，处理页面级生命周期   | 是         | 否           |
| Container | 数据获取和状态管理，向子组件分发数据           | 是         | 是           |
| Component | 纯展示/交互，通过 Props 接收数据，emit 事件    | 否（或局部） | 否         |

## 拆分原则

- **单一职责**：一个组件只做一件事
- **100行原则**：组件模板超过 100 行考虑拆分
- **复用优先**：超过 2 处相似 UI 必须抽取为公共组件
- **避免深层 Props Drilling**：超过 3 层透传改用 provide/inject 或 Store

## 命名规范

- 组件文件名：大驼峰，`OrderList.vue`、`OrderDetailCard.vue`
- 目录结构：`src/pages/{模块}/components/{组件名}.vue`
- 公共组件放 `src/components/`

## Props 设计

- Props 类型必须明确声明（TypeScript interface 或 defineProps withDefaults）
- 复杂对象 Props 定义独立的 TypeScript interface
- Props 只传必要的数据，不传整个对象再在子组件里取字段

## 组件通信

| 场景                         | 方案                    |
| ---------------------------- | ----------------------- |
| 父 → 子                      | Props                   |
| 子 → 父                      | Emit                    |
| 跨层级（祖 → 孙）            | provide/inject          |
| 跨组件树（兄弟、远亲）       | Pinia Store             |
| 页面间传递复杂数据           | Pinia Store（不用路由大量传参） |

# 组件与字段规范（§4.4 · `fe-component-field`）

合并 **既有资产复用** 与 **新增/改造业务组件** 的设计约束。

---

## 项目框架约束（重要）：Vue 写法

- **必须**：使用 **Vue 3 Composition API**，组合式 API 从 **`vue-demi`** 引入。
- **禁止**：**Vue 2 Options API**（`export default { data, methods, computed, … }` 等）。
- 组件类型与拆分逻辑仍适用；逻辑封装优先 **composable / hooks** 风格（与脚手架一致）。

---

## 适用性

- **复用**：凡直接使用 UI 库、项目公共组件、Composable 的条目须在模板「复用」段声明。
- **新增/改造**：新 Page/Container/Component 或字段无法在复用层表达时，在「新增」段展开组件树与字段表。

---

## 复用原则

- 先盘点可复用资产，避免重复造轮子；复用段为**声明式引用**，不写实现正文。
- 需改公共组件 Props/Slot 或扩展字段绑定时，在「新增/改造」段评估影响；**DFX** 中「公共组件抽取」见 `fe-nfr`。

---

## 组件类型与拆分

| 类型 | 职责 | 状态 | 调 API |
| ---- | ---- | ---- | ------ |
| Page | 页面入口、组合子层 | 是 | 不经由 service 的约定除外 |
| Container | 取数、状态、下发 | 是 | 通过 `useService()`（见 `fe-api-data`） |
| Component | 展示/交互 | 局部或无 | 否 |

- 单一职责；模板过长考虑拆分；跨 2 处相似 UI 优先抽取。
- 命名：大驼峰文件；页面内组件 `src/pages/{模块}/components/`；公共 `src/components/`。

## Props / 通信

- Props 类型须明确；勿深层透传超过 3 层（改用 provide/inject 或 Store）。
- 通信：Props / Emit / provide-inject / Pinia；页面间复杂数据走 Store。

---

## 项目规范摘录（`it_design_doc.md` §4.8.3 · 组件与字段）

- **表格列**：序号、列标题、`field`、列类型、排序、筛选、备注。
- **表单字段**：标签、字段名、**脚手架组件类型**、必填、校验、备注（组件名与 linkjs/Turbo 组件库一致）。
- **枚举**：`label` / `value` / 展示样式；Lookup 写明 key 与批量查询方式。
