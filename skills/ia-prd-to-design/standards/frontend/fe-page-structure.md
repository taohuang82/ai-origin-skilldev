### 规范条文

# 路由信息设计规范（§4.2 · `fe-route-design`）

对应要素：**路由信息设计**。在 **新增页面目录、功能入口变更或权限展示变更**时展开；目录清单不变时可省略。

---

## 适用性（强制）

| 情形 | 处理 |
| ---- | ---- |
| 新增/变更**页面目录名**或与目录绑定的功能 ID、权限说明 | 更新路由表 |
| 仅改组件/接口/交互，**页面目录与外部注册关系不变** | **省略**或一行说明「路由目录无变更」 |

权限要求文字可与 `config.md` → `## §6.3 权限矩阵` **对齐引用**，不在本节重新定义权限模型。

---

## 项目框架约束（重要）

### 一级目录与外部注册

- **必须**：每个页面对应 **唯一一级目录名**（路径表现为单层，例如 `/tag-management`）。
- **禁止**：**二级路由路径**（例如 ~~`/tag-management/maintain`~~）；不得以嵌套路由表达子页面。
- **声明范围**：技术方案中**只声明目录名与业务含义**，**不写** `router` 配置代码；**目录创建与路由注册在外部系统完成**，方案中忽略注册实现。
- **详情 / 子状态**：通过 **Query** 传参（如 `id`），或通过父页面内状态切换；**禁止**用额外路径段表达。
- **弹窗 / 对话框**：**不需要路由**；在父页面通过 **visibility**（显隐）控制。

### 命名建议

- 目录名：小写、连字符，与业务含义一致（如 `tag-management`、`resource-detail`）。

---

## 与设计文档的关系

- 若有高保真设计稿，页面与设计稿索引仍可按团队 `it_design_doc.md` 约定单独维护（模板可选章节）。
- 「前端定位信息」可与目录名、功能 ID 对照填写。

### 规范条文

# 布局结构规范（§4.3 · `fe-layout`）

对应要素：**布局结构**。描述页面所用 Layout 壳与内容区分区，与设计稿 / `docs/init/FRONTEND_PAGE_DESIGN.md` 对齐。

---

## 适用性（强制）

- 凡本次 **✨ / 🔧** 涉及的页面均应评估布局（增量从简：未动页面不写）。
- 仅后端或纯接口变更不涉及页面时可省略本节。

---

## 编写要求

- 标明：**Layout 类型**（默认框架壳、空白、模块自定义壳等）。
- **内容区纵向分区**：筛选区、工具栏、表格/列表、表单区、**弹窗/抽屉（不占路由，父页 visibility）** 等。
- 栅格、间距、响应式须符合 **linkjs / Turbo 脚手架** 与团队 UI 规范（详见工程文档）；方案中不写具体像素堆砌时可引用设计稿编号。

---

## 项目规范摘录

### 页面布局区域（`it_ux.md`）

- 典型：**顶栏**、**侧栏**、**内容区**、**页脚**（若有）。
- 内容区常见：文案、控件、表格/卡片、表单、图标与标签。

### 设计稿（`it_design_doc.md` §4.7）

- 有高保真时须先读理解文档再定分区；禁止臆造或与稿不一致的层级删减。
