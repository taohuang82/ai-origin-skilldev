# 外部服务依赖规范（TDD 第5章 §5.2）

## 适用场景

本要素记录本系统**跨业务边界调用外部系统**的依赖契约，包括：
- 调用其他微服务（FeignClient / HTTP）
- 调用第三方平台（支付、短信、地图、OCR 等）
- 调用组织架构、用户中心等**独立部署的基础业务服务**

## 不属于本要素

以下能力由 **Jalor / IAOne 平台框架或二方件**提供，属于框架内置用法或平台 SDK 接入，**不得**作为 §5.2 外部服务依赖输出：

| 能力 | 应归属要素 |
|------|-----------|
| Jalor 权限注解（`@JalorResource` / `@JalorOperation`） | `config-permission` |
| Jalor Lookup / 数据字典查询 | `config-dict` / `config-app-config` |
| Jalor 异步任务、框架内置 MQ 封装 | `backend/be-schedule` 或 `architecture/arch-tech-stack` |
| Jalor Excel 导入 / 导出 | `backend/be-export` |
| Jalor 业务异常与错误码 | `config-error-code` |
| IAOne 审批流 SDK | `backend/be-workflow` |
| Todos / Espace / EDM 等平台 SDK | 对应 `backend` 实现要素（按业务场景） |

> 判断原则：若依赖的是**平台框架 API / SDK 用法**而非**独立外部系统的 HTTP/RPC 契约**，则不属于集成域。

## 依赖声明原则

- 每个外部依赖必须声明超时（connectTimeout + readTimeout）
- 必须有熔断器（Resilience4j / Sentinel）保护
- 必须有降级返回值（不允许返回 null 后直接使用）
- 同步调用不能超过 3 跳（避免调用链过深）

## 超时配置规范

| 场景 | connectTimeout 建议 | readTimeout 建议 |
|------|-------------------|----------------|
| 内部微服务 | 500ms | 2000ms |
| 组织架构等基础服务 | 500ms | 3000ms |
| 第三方平台（支付/短信） | 1000ms | 5000ms |
| 数据密集型接口 | 500ms | 10000ms |

## 熔断器配置规范

- 失败率阈值：50%（超过此比例触发熔断）
- 慢调用阈值：P95 > 2s 视为慢调用
- 熔断持续时间：30s（进入半开状态后探测恢复）
- 最小调用数：10 次（样本量不足时不触发熔断）

## 降级策略规范

| 降级类型 | 适用场景 | 示例 |
|---------|---------|------|
| 返回默认值 | 查询类，结果不影响主流程 | 获取用户头像失败返回默认头像 |
| 返回缓存值 | 数据变化不频繁 | 组织架构信息返回本地缓存 |
| 跳过操作 | 非核心操作 | 发送通知失败不影响主业务 |
| 抛出业务异常 | 核心操作不可降级 | 支付结果查询失败必须终止 |

## 重试策略规范

- 重试仅适用于网络抖动等**可重试错误**（超时、5xx）
- 业务错误（4xx、参数错误）不重试
- 最多重试 2 次，使用指数退避（1s、2s）
- 重试时注意接口幂等性（GET / 幂等 POST 可重试）
